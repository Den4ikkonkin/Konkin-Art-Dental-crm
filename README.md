# Dental Studio — облачная версия

Та же лаборатория, что и в локальном проекте, но данные хранятся на сервере
Supabase. Открывайте с любого устройства, где есть вход в аккаунт.

## Запуск

```bash
npm ci
npm run dev
```

Откройте http://localhost:3001.

Перед первым запуском обязательно выполните `supabase/migrations/0001_init.sql`
в SQL Editor вашего проекта. Файл можно запускать повторно — он не удаляет данные.

## Что нового по сравнению с локальной версией

- **Данные на сервере.** Наряды, пациенты и выплаты доступны с любого устройства.
- **Вход по аккаунту.** Экран авторизации, выход из аккаунта, данные привязаны к пользователю.
- **Файлы пациентов.** Вкладка «Файлы» у пациента: фото, сканы, PDF, до 25 МБ на файл.
- **Светлая и тёмная тема.** Переключатель в верхней панели и в настройках.
- **Календарь с пациентами.** В клетках дня видны фамилии, при клике — список.
- **Пациенты с нарядами.** В карточке пациента сразу видно его наряды, суммы и оплаты.

## Безопасность

Публичный ключ (anon / publishable) находится во фронтенде — это нормально:
доступ к строкам ограничивают RLS-политики в базе, каждый видит только свои записи.
Файлы лежат в приватном хранилище и открываются по временной подписанной ссылке.

Ключ `service_role` обходит все политики и не должен попадать в браузер,
в репозиторий или в чат. В файле `.env.local` его быть не должно.

Для рабочего использования на реальных пациентах добавьте: подтверждение почты,
сложные пароли, регулярные резервные копии и защищённый сервер.

## Хранение файлов и объём

Free-план Supabase даёт 1 ГБ хранилища и 500 МБ базы. Для фото и сканов этого
обычно хватает на несколько сотен файлов. Когда места станет мало:

- Pro-план Supabase — 100 ГБ хранилища, 8 ГБ базы, ежедневные копии.
- Собственное хранилище (Backblaze B2, Cloudflare R2) — дешевле при больших объёмах.
- Архив старых снимков: выгружать на диск и удалять из облака.

Приложение рассчитано на замену хранилища одним файлом `src/lib/db.ts`.

## Схема данных

- `patients` — пациенты.
- `orders` — наряды, позиции работ в поле `items` (jsonb).
- `salary_payments` — фактические выплаты оклада.
- `settings` — план оклада.
- `patient_files` — описание файлов; сами файлы в bucket `patient-files`.

## Проверки

```bash
npm run typecheck
npm test
npm run build
```

Проверено в браузере: экран входа, обе темы, отсутствие ошибок JavaScript.

## Ограничения текущей версии

- В базе нет журнала платежей: поле «Оплачено» — сумма по наряду.
- «Готово» считается по статусу наряда, не по каждой позиции.
- Совместная работа нескольких пользователей одновременно не проверялась.
- Автоматического переноса данных из старого проекта нет: пациент заводится вручную.
